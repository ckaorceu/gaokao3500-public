# 界面优化 (2026-08-01)

## 用户指令
"优化界面"（开放式）。采用做法：截图 → 视觉模型指出具体视觉问题 → 针对性修复 → 截图+代码级断言验证。

## 修复项
1. 首页单词卡：`.word-card` 是 `<a>` 继承了浏览器默认蓝字+下划线 → 加 `text-decoration:none; color:var(--text)`，英文深色、释义 `var(--muted)` 灰色次级。
2. 进度块分组：用 `renderStats` 把"未学"单独放「学习状态」组，"L1-L5"放「复习等级」组，各自小标题。
3. 筛选栏三控件统一 `height:40px`、同圆角对齐。
4. 学习页 Tab：原本激活态"膨胀"，改统一尺寸仅靠背景色区分（CSS 本就统一，已 OK）。
5. 评级按钮：做成 `.rbtn` 独立类（flex:1 等宽），语义色：不会=红/熟记=绿，中间两档中性。原"不认识"改"不会"避免 3 字换行。
6. 卡片留白：padding 36→30、min-height 240→200，更紧凑。

## 关键坑（重要）
**空 CSS 块导致后续全部规则失效**：第一次编辑误把 `.learn-meta {` 变成空块（缺属性、缺右括号），Chromium 解析到该处直接丢弃后续所有规则（`.actions`/`.rbtn`/`.trick` 全失效）。现象：所有后续样式不生效，但 CSS 文件响应式体里明明有规则。
排查方法：`document.styleSheets[0].cssRules` 只解析出 71 条且最后一条是 `.mode-tabs button:hover`，后面全无 → 定位到缺失的右括号。
**教训**：改 CSS 结构性替换（整块替换）后，必须用 Playwright 断言关键规则是否真正生效（不能只看文件内容），或本地做 CSS 语法校验。

- `verify_modes.py` 功能回归：3 模式 + 巧记持久化全部 PASS，0 JS 错误。
